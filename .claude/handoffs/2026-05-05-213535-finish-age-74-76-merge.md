## Codebase Understanding

## Architecture Overview

- **Two coexisting frontends in the same repo**:
  - `next dev` / `next build` (Next.js App Router) — uses `public/` for static assets, `next/image` for images.
  - `vite build --config vite.config.mts` aka `npm run build:tanstack` — TanStack Start. Emits SSR Worker bundle to `dist/server/index.mjs` and client bundle to `dist/client/`. This is the production deploy path.
- **Production deploy** (`cd-prod` on push to `main`): builds TanStack Start, runs `npm run iac:deploy -- --stage prod` which executes `alchemy.run.ts` → `appStack(...)` in `alchemy/app.ts`. The Worker is `code-colony-app`, bound to apex `https://app.codecolony.online/`.
- **Static Assets pattern (the AGE-74 fix)**: Cloudflare Workers serves files matching paths in the `ASSETS` binding directly (without invoking the Worker). For unmatched paths, the SSR Worker (`dist/server/index.mjs`) runs. Without this binding, every `/assets/*.{js,css}` request hit the SSR Worker, which had no asset-serving logic, and 404'd.
- **Alchemy `Assets()` is a plain factory function** in v≥0.69 (was a Resource constructor before). Signature: `Assets(props: { path: string }) → Promise<{ type: "assets"; path: string }>`. **Do not pass an ID like `Worker(id, props)` — first attempt did this and crashed deploy with `TypeError [ERR_INVALID_ARG_TYPE]: The "path" argument must be of type string ... Received undefined` from `readDirectory` in `alchemy/lib/cloudflare/assets.js:50`.**

### Key Patterns Discovered

- **Alchemy package not in `package.json`**: It is installed at deploy time in CI via `npm install --no-save alchemy` (no version pin). Any breaking-change minor release of Alchemy will surface as a deploy failure, not a build failure. The `Assets()` signature change between Resource-style and factory-style is exactly that risk realised. Pre-existing concern, not in scope for AGE-74/76 — flag as a follow-up.
- **`build:tanstack` fails locally because the repo path contains a space** (`Code Colony`). `vite.config.mts` uses `new URL("./src", import.meta.url).pathname`, which URL-encodes spaces as `%20` and rolldown then can't resolve `@/domain/*` aliases. CI works because the runner path has no spaces. Skip local builds; rely on CI.
- **Typecheck via `npm run typecheck` (`tsc --noEmit`)** is fine locally. Tests via `npm test` are fine locally.
- **PR template / commit format**: Uses Conventional Commits with the AGE-XX scope. PRs are squash-merged into `main`. README contributor section says "rebase/fast-forward" but the actual practice is squash. PR #91 used a manual squash commit message; PR #92 should follow the same pattern (see Immediate Next Steps).
