01

Design Principles

Ten rules that govern every screen, asset, and animation. When two principles fight, "every artifact is reviewable" wins.

  • Project as playable boardThe repo is a world. Districts, rooms, agents, and tracks are first-class — not metaphors layered on a dashboard.
  • Specs before executionMeaningful work begins as a spec card. Cards must be drawn, debated, voted, and placed before agents move.
  • Every artifact is reviewableDiffs, ADRs, memories, skill updates — all surface as bundles a human can approve, reject, or request changes on.
  • Risk and trust are visibleTwo persistent tracks on every screen. Color, position, and pixel weight all reinforce them.
  • Modular over bespokeTiles, frames, tokens, and standees are composed from a small library. No hero illustrations.
  • Professional first, whimsical secondPixel and tabletop are tone, not theme. Copy stays operational; humor is rare and earned.
  • Multiplayer decisions are obviousWho voted, who hasn't, who's watching, who's working — visible without opening a panel.
  • Memory and learning are tangibleMemories are crystals. Skills level up with audible/visible ceremony. They are objects, not log lines.
  • Readable pixelsPixel for headings, KPIs, and labels. Sans-serif for any body text longer than a line.
  • AI-generatable assetsEvery asset has a fixed grid, palette slot, and naming pattern. An agent can generate a new tile and slot it in with no manual touch-up.

Visual Identity

Mood, art direction, density, and the line we walk between pixel-art game and developer tool.

Mood Board

DATA DISTRICT
FRONTEND

Dark navy felt under warm parchment cards. Pixel sprites lit from upper-left. Brass and gold trim on important frames; everything else is restrained.

Art Direction Rules
  • Pixel density: 1× sprites at 16/32/64/128Drawn at native size, never upscaled with smoothing. Display at 2× via CSS for hi-DPI.
  • Limited palette per assetEach tile uses at most 6 colors drawn from a single domain ramp. Status is applied as an outline color, not by repainting the sprite.
  • Lighting is consistentLight source upper-left at ~30°. Highlights are 1–2 pixels; shadows are darkened ramp colors, never pure black.
  • Avoid clutterMap shows districts; rooms only appear at zoom ≥ 2. Tokens and standees never overlap text.
  • Text is sansPixel font is for <3-word labels and KPIs only. Anything longer breaks readability.
Influence — Pixel Sim
Tile-based world, side-on standees, modular buildings, day/night ambient lighting (subtle, not literal).
Influence — Tabletop
Card frames with caption strips, board tracks with cells, polyhedral approval tokens, brass corner brackets on hero frames.
Influence — Developer Tool
Monospace diffs, clear info density, keyboard-first controls, no animations on critical numerics.
Avoid
Fantasy iconography in v1, hand-drawn illustrations, gradient-heavy hero art, neon glow, cute-mascots-as-employees.

08

Asset Generation System

Fixed grids, palette slots, and naming so an agent can produce a new tile/icon/standee that drops in with no manual touch-up.

Icon — small
16×16 px · 1× sprite · transparent PNG · ≤ 4 colors from one ramp.
Icon — large
32×32 px · 1× sprite · transparent PNG · ≤ 6 colors.
Standee
64×80 px · base 64×64 sprite + 16px shadow strip · 6-color palette: skin, hair, shirt, pants, accent, outline.
Room tile
128×128 px · footprint 96×88 with 32px ground strip · roof, wall, door, window slots; flag & accent slot for status.
Region tile
256×192 px · base + nameplate slot + 4 connection anchors (N/E/S/W).
Card frame
9-slice PNG: corners 12×12, edges 4px, body parchment-100. One frame, six cap colors.
Token
44×44 px circle on dark · 28×28 small variant. Drawn from 9 palette slots.
UI panel
9-slice navy frame: 8px corners, 1px hairline edges, 2px inner highlight. One panel, three border weights.

NAMING CONVENTION

/assets/
├── icon/16/{name}.png             # icon-16-spec.png, icon-16-risk.png
├── icon/32/{name}.png
├── standee/64/{role}-{variant}.png # standee-64-frontend-01.png
├── room/128/{type}-{state}.png    # room-128-planning-idle.png
├── region/256/{district}.png      # region-256-auth.png
├── card/frame/{type}.9.png        # card-frame-spec.9.png
├── token/44/{kind}.png            # token-44-approve.png
├── ui/panel/{weight}.9.png        # ui-panel-1.9.png
└── palette/{name}.gpl             # palette-base.gpl, palette-auth.gpl

PALETTE SLOTS & STATUS RECOLORING

Layering rules
Each sprite has these layers, in order: shadow → base → detail → outline → status accent. Status is applied by swapping the accent layer color only — never the base.
Variants
Generate all variants by recoloring slots 1–6. Idle / hover / selected / working / blocked produced from the same base sprite.
Export
PNG, indexed-color preferred, no anti-aliasing, transparent background. Companion `.json` lists palette slot mapping.
Validation
An agent producing a tile must pass: correct dimensions, ≤ N colors, all colors present in declared palette, transparent margin pixels not painted.

React + PixiJS Implementation

Pixi owns the world canvas and animations. React owns forms, panels, and any text-heavy surface.

PIXI · CANVAS LAYER
  • World mapRegion tiles, connections, zoom/pan, parallax.
  • Room tiles128px buildings, hover lift, selected glow.
  • AgentsStandees with idle bob, walk, work animations.
  • Tokens on boardApproval/risk tokens placed on cards/cells.
  • AnimationsMemory crystallization, ultrawork burst, incident shake.
  • AnnotationsSisyphus speech bubbles and pin markers.
REACT · DOM OVERLAY
  • App shellTopbar, rails, tray, modals.
  • FormsSpec editor, ADR editor, agent loadout.
  • PanelsSisyphus feed, advisor, agent panel, room panel.
  • ReviewDiff viewer, file tree, comments — all DOM.
  • MarketplaceCards in HTML, install drawer, search.
  • Memory viewsLists, filters, detail panes.
Map structure
Pixi `Container` per district → child `Container`s for rooms → sprite per agent. Cull off-screen at low zoom.
Zoom levels
Z0 world (regions only) · Z1 districts (rooms) · Z2 rooms (agents + standees) · Z3 inside-room (boards/cards as DOM modal).
Hover/click
Pixi emits hit events; React renders the tooltip / nameplate as an absolutely-positioned DOM element above the canvas.
Multiplayer presence
Each remote user is a small standee with name pill at their last-known coordinate. Cursors throttled to 10Hz.
Text rule
Any string longer than a 3-word label is DOM. Pixi gets pixel labels only (BitmapText with Press Start 2P).
Forms in Pixi?
Never. The moment a screen needs an input, table, or scroll list, it's React.

Every interactive element has these visual states. Apply via outline + token, never by repainting the base sprite.

Default appearance. No outline.
Hover
1px gold outline, +2px lift via shadow.
Selected
2px gold outline, persists.

Blocked

Needs approval
Gold dashed outline + small "approve" token in upper-right.
In review
Yellow tint band along the bottom edge.
Approved
Green checkmark token in upper-right.
Rejected

Changes requested
Yellow ~ token + striped yellow band.

Red outline shake (8px, 2 cycles) + incident token attached.

Trust increasing

Motion & Animation

Short, snappy, pixel-stepped. No long eases on critical numerics. Reduced-motion users get instant transitions.

Agent walk
2-frame loop, 6 fps, 16-pixel step. Path interpolation linear; sprite frames stepped.
Token placement
120ms drop with 1 bounce. 8px overshoot, settle.
Card draw
200ms slide-up + tilt 4°, then settle. Reveal flips at 100ms.
Approval vote
Token snaps to slot in 80ms. Tally pip increments with a tick.
Risk alert
Risk token shake 8px ×2; district outline pulses red for 1.5s.
Trust increase
+N floater, 600ms upward fade. Track cell paint-fills 240ms.
Memory crystallization
1.2s spawn → drift to vault. Sparkle particles, 6 max, pixel-snapped.
Skill update
Card flip 320ms; chime if sound enabled; lands on Memory panel.
Incident escalation
Screen-edge red vignette 200ms in / 600ms hold / 400ms out. Single shake.
Sisyphus annotation
Speech-bubble pop 160ms with type-on caret 30ms/char up to 80 chars.
World upgrade/decay
Tile cross-fade 400ms between idle / upgraded / decayed variants.
Curves
cubic-bezier(.2,.7,.1,1) for UI; stepped() for sprites. Default duration 160ms.
12

Accessibility & Readability

Pixel aesthetic must not compromise comprehension. Color is never the sole signal.

Min text size
Body 13px / Pixel labels 9px / Mono 12px. Never smaller.
Contrast
4.5:1 for body on bg-panel; 3:1 for pixel labels (treated as large text).
Colorblind safety
Risk = red + ! glyph. Trust = green + ★. Approval = green + ✓. Reject = red + ✗. Always pair color with shape.
Icon + text
All status tokens carry a glyph. Never icon-only at sizes ≥ 28px.
Reduced motion
`prefers-reduced-motion` disables shake, particles, and card flips. Token snaps replace bounces.
Keyboard
Full panel-and-tray nav with Tab; ←/→ moves between cards; Enter approves; Esc closes modal. Visible focus ring: 2px gold.
Screen reader
All Pixi-rendered states mirrored in a hidden DOM live region. Cards expose `role=button`, tokens `aria-pressed`.
Pixel font in body
Forbidden. Auto-replace any pixel-font paragraph with body sans in user CSS overrides.
13

Theming & Future Skins

v1 ships professional pixel + tabletop. Future skins swap palette slots and frame ornaments without changing layout.

Sci-fi skin
Steel/cyan palette, hex-grid maps, holographic frames. Same components, swap roof/wall sprites.
Fantasy skin
Wood and brass, hand-lettered card caps, parchment intensified. Reserved — do not enable in v1.
Enterprise clean
Drop pixel sprites; keep card frames flat. Pixel font reserved for KPIs only. For audited corporate buyers.
Cozy office
Warmer tones, plant tiles in rooms, softer trust colors. For long-running marathons.
Dark ops / cyber
Black + monochrome cyan, glitched outlines on incidents. Highest visual cost — gated.
Skin packaging
A skin is a directory: palette.gpl + sprites/ + ornaments.svg + theme.json. Loaded at runtime.
